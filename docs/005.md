# Administração do sistema

Este documento descreve a área administrativa do ATestaPonto. A autenticação Gov.br/OIDC está detalhada em [006.md](./006.md).

## Papel do administrador

O administrador acompanha a operação do ponto escolar. Ele não registra ponto como funcionário dentro do fluxo administrativo.

Principais responsabilidades:

- acessar o dashboard protegido;
- cadastrar funcionários;
- consultar funcionários;
- editar dados administrativos;
- desativar ou reativar funcionários;
- consultar presença do dia;
- gerar relatórios;
- gerenciar o atalho de QR Code.

## Proteção do painel

As páginas administrativas passam pelo middleware de sessão. Se `req.session.admin` não existir, o usuário é enviado para o fluxo Gov.br/OIDC.

As APIs administrativas usam um middleware próprio que também verifica a sessão e a autorização interna.

## Funcionários

O cadastro de funcionário cria, em uma transação:

1. o cargo com os horários daquele funcionário;
2. o registro do funcionário;
3. o login do funcionário com senha temporária em hash.

A senha temporária é retornada uma única vez na resposta do cadastro. Por isso, a resposta usa cabeçalhos para evitar cache.

## Edição

A edição permite alterar campos administrativos como:

- nome;
- e-mail;
- telefone;
- cargo;
- horários do cargo.

O CPF não está entre os campos editáveis do fluxo administrativo atual. Essa decisão reduz o risco de alterar o identificador principal do funcionário sem um processo específico.

## Desativação e reativação

A mudança de status exige confirmação textual:

| Ação | Confirmação esperada |
| --- | --- |
| Desativar | `DESATIVAR` |
| Reativar | `REATIVAR` |

Isso evita alteração acidental de status. Um funcionário inativo não consegue registrar ponto.

## Pontos e relatórios

O painel administrativo consulta:

- presentes;
- ausentes;
- total de funcionários;
- total de funcionários ativos;
- taxa de presença;
- lista detalhada das batidas do dia.

O relatório não altera dados: ele monta uma visão em memória a partir dos funcionários e dos registros existentes para a data solicitada.

## QR Code administrativo

O back-end simula uma interface de CRUD para QR Code, mas o conteúdo atual é um atalho fixo para `/ponto/acessar`.

Isso significa que desativar o QR Code não altera um token persistido em banco, porque o atalho não é dinâmico no estado atual do projeto.

## Rotas relacionadas

| Método | Rota | Função |
| --- | --- | --- |
| `GET` | `/admin/dashboard` | Página principal do painel. |
| `GET` | `/api/admin/auth/me` | Consulta a sessão admin. |
| `GET` | `/api/admin/funcionarios` | Lista funcionários. |
| `POST` | `/api/admin/funcionarios` | Cadastra funcionário. |
| `GET` | `/api/admin/funcionarios/:id` | Consulta funcionário para edição. |
| `PATCH` | `/api/admin/funcionarios/:id` | Edita funcionário. |
| `PATCH` | `/api/admin/funcionarios/:id/desativar` | Desativa funcionário. |
| `PATCH` | `/api/admin/funcionarios/:id/reativar` | Reativa funcionário. |
| `GET` | `/api/admin/cargos` | Lista cargos. |
| `GET` | `/api/admin/pontos/hoje` | Consulta presença por data. |
| `GET` | `/api/admin/pontos/relatorio` | Gera relatório diário. |
| `GET` | `/api/admin/pontos/resumo` | Consulta resumo do dashboard. |
