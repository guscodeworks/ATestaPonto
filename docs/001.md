# Objetivos e escopo

Este documento define o que o ATestaPonto pretende entregar e quais limites foram assumidos no estado atual do projeto. A motivação e o contexto do problema estão na [introdução](./000.md).

## Objetivo geral

Desenvolver um sistema web para controle de ponto escolar, permitindo que funcionários registrem sua jornada de forma digital e que administradores acompanhem cadastros, presenças e relatórios.

## Objetivos específicos

| Objetivo | Por que existe |
| --- | --- |
| Registrar ponto digitalmente | Substituir o caderno físico por registros persistidos em banco de dados. |
| Autenticar funcionários | Garantir que a batida seja associada a um funcionário cadastrado. |
| Validar localização | Reduzir o risco de marcação remota fora da área definida para a escola. |
| Controlar quatro batidas diárias | Representar entrada, saída para almoço, retorno do almoço e saída. |
| Gerenciar funcionários | Permitir cadastro, consulta, edição, desativação e reativação. |
| Gerar visão administrativa | Apoiar o acompanhamento de presença, ausências e relatórios diários. |
| Simular Gov.br localmente | Demonstrar o fluxo administrativo enquanto a integração oficial não está configurada. |

## Escopo funcional

O sistema principal cobre:

- telas web para funcionário e administrador;
- APIs para login de funcionário, registro de ponto e administração;
- autenticação administrativa por fluxo Gov.br/OIDC ou simulador local;
- autorização administrativa interna por `sub` ou e-mail;
- validação de entrada com middlewares;
- persistência em MySQL;
- geração de atalho de QR Code para a tela de ponto.

## Fora do escopo atual

O projeto não declara suporte completo para:

- produção real sem ajustes de infraestrutura;
- integração oficial final com Gov.br, pois depende de credenciais e endpoints oficiais;
- aplicativo mobile nativo;
- ponto offline;
- biometria;
- painel de professor separado do painel administrativo;
- múltiplas escolas com configuração independente no mesmo banco;
- auditoria completa em tabela própria, já que o serviço atual registra eventos no log da aplicação.
